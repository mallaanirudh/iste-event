# FeISTEval homepage

`app/page.tsx` renders `festival-home.tsx`. The homepage uses Tailwind 4, Bangers and Nunito, plus Fredoka for the desktop title's mixed-case lettering (self-hosted through `next/font/google`), Lucide icons, and local SVG artwork. `festival.css` scopes the animation, artwork, and chamber feedback to the festival components.

The ten refinements recorded in root `UI_CHANGE_LOG.md` are currently enabled: `design-refinements.ts` contains their independent numbered switches. `festival-refinements.css` scopes each CSS group to its number; optional artwork, ranking, labels, gate details and footer markup use the same switches. The active homepage uses Fredoka (600/700) headings and Nunito body text. Setting an individual switch to false restores only its corresponding refinement; the original Bangers styling and prior markup remain available as fallbacks. An exact local baseline is stored at `C:/Windows/Temp/iste-ui-before-ten-2026-10-08`.

## Content and configuration

- `chamber-data.ts` preserves all six original chamber titles, descriptions, themes, and ordering from `HomePageComponents/InventingRoomsSection.tsx` at pulled commit `7b793b2`. The dashboard previews Scotland Yard and uses Charge's existing event name, tagline, and start time. The five leaderboard examples come from the original homepage's fallback data and remain clearly labeled; they are not published results.
- `data/registration.ts` owns the shared registration website, `https://feisteval-2026.vercel.app`. Homepage Golden Tickets and active event registration actions open it in a new tab. No Tally form ID is required for these links.
- The existing server-only API integration remains in `lib/api/`; connecting the new dashboard to live data requires actual backend configuration and event IDs. Never put database or Tally API credentials in public environment variables.

## Schedule and current/upcoming events

`data/festival-schedule.ts` is the source for all published dates and timing windows from the supplied October 2026 brief. Scotland Yard is 11 October (9 AM–1 PM, 3–5 PM and 6–7 PM). Concrete, Clutch, Crypt and Catalyst use the shared 6:30–8:30 PM Square One slot on 12, 13, 15 and 16 October respectively. Charge uses the more specific 14 October slots (6–8 PM and 9–11 PM); this overrides the brief's common slot unless the organizer clarifies otherwise.

`festival-events.tsx` replaces the old fixed Scotland Yard/Charge preview cards with clock-based current and next sessions. Session starts are inclusive and ends exclusive, breaks are not live, and the final ongoing event remains live even when no next event exists. The upcoming card advances to the next round or next event and shows a completed state after 16 October at 8:30 PM. Explicit +05:30 timestamps and `Asia/Kolkata` formatting keep the schedule in IST regardless of the visitor's timezone. The clock refreshes each second while visible and immediately on returning to a tab. No event status is written to the backend.

The complete calendar and chamber dates are rendered as page content. Event pages reuse the same date/timing source. Run `npm run test:schedule` on Node 24+ for timing-boundary tests. These automatic states reflect the published timetable; they do not replace organizer-confirmed backend results.

## Interaction and layout

- `festival-hero.tsx` adapts the old homepage's entrance to the current night-carnival palette: centered FeISTEval lettering with yellow ISTE, a small unboxed label, one short introduction, one Enter Carnival action, and a compact carnival illustration. Peripheral gate panels open outward as the visitor scrolls, while the center scales from 0.97 to 1. The title and action remain visible throughout.
- The hero has three rows: bunting, entrance scene, and festival strip. The bunting has a 24px gap on mobile and 16px on desktop. Gates belong to the scene, so their bottom edges cannot cover the strip. The strip stays with the pinned hero instead of following its extra scroll space. Desktop title and illustration sizes respond to viewport height; the hero's minimum height allows the entire entrance to occupy the space below the 85px navbar and grow if needed on shorter screens. Mobile keeps intrinsic content flow.
- Entrance pinning is limited to fine-pointer, hover-capable desktops at least 1024px wide and 800px tall, with reduced motion off, and is skipped if the hero cannot fit below the navigation. The pinned entrance starts 85px below the viewport top to clear the full-height navbar. Its extra scroll distance is 40% of the viewport height, capped at 320px. Touch, small screens, reduced motion, and no-JavaScript rendering keep native flow. GSAP's media context reverts the pin and transforms on breakpoint/preference changes and unmount.
- Desktop dashboard: two columns, featured chamber above upcoming event on the left, leaderboard spanning both rows on the right. Below 768px, the cards stack in featured / upcoming / leaderboard order.
- The dashboard and alternating chamber cards borrow the original noticeboard framing: brass/gold outlines, small corner rivets, solid offset shadows, inset chamber nameplates, and ticket-like actions. Pink and cyan remain accents inside the twilight palette. Footer signs share the same framing. Hover feedback uses small translations; there are no animated page backgrounds or large blur effects.
- Desktop chamber cards use 42% of the journey width, capped at 440px. The ending label sizes to its text and stays in normal flow, with 96px clearance after the final card on mobile and 128px on desktop. The gate containers are capped at 184px and their SVGs preserve aspect ratio, keeping the stars and circular ornaments proportional. Connector paths and masks still measure the stationary card wrappers after resizing.
- `chamber-journey.tsx` restores the original alternating, connected layout. Its SVG path follows measured stationary card wrappers, updates after font loading and resize, and draws with scroll progress through GSAP ScrollTrigger. A shared SVG mask hides every connector stroke and the moving spark inside the chamber footprints, including entry/hover movement. The mobile rail is hidden beside each chamber and remains visible in the gaps. Attachment dots were removed; the curves between chambers remain. `chamber-art.tsx` supplies distinct illustrations for the six original themes.
- Five chamber actions lead to the correct routes. Crypt has no dedicated event route in the source repository, so it opens an honest preview with its original text. Concrete now renders the existing nautical component kit instead of the duplicated Clutch racing page.
- `festival-navbar.tsx` adapts the Desktop AeroNITK project's `website_aero/src/components/header.jsx` and `header.css` behavior: after 50px of scroll the fixed desktop bar shrinks from 85px to 70px, the brand fades/collapses, and animated flex spacers center the links. At 900px and below, the brand remains visible and navigation opens in a full-screen native dialog with keyboard focus containment, Escape dismissal, scroll locking, and desktop-resize cleanup. Colors and typography belong to FeISTEval; no AeroNITK global CSS is imported.
- The full leaderboard searches by team/chamber. Entry reveals, measured scroll progression, card feedback, fixed navigation, and native dialog transitions support the browsing flow. Decorative motion is limited, and the CTA remains steady.
- Dialogs use native focus containment, Escape dismissal, a close button, and outside dismissal. Anchor scrolling, entry animations, and decorative motion respect reduced-motion preferences. Content remains visible when JavaScript is unavailable.
- The countdown clamps at zero once the configured Charge event date passes.
